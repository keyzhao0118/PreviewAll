# 测试样张维护规则

本文件约束 `test/` 内的样张、生成脚本和说明。根目录 `AGENTS.md` 的预览开发规范仍然适用。

1. 以 `PreviewAll/preview/previewpagefactory.cpp` 的扩展名列表为唯一格式范围。每个已注册扩展名都必须有一份真实可预览的基础样张，并在 `switching/` 中恰好出现一次。文件名用两位数字前缀固定顺序，交错排列图片、压缩包和 Markdown，便于在同一资源管理器窗口反复顺向、逆向切换并跟踪 Handler/IPC 时序。新增类型时同步扩展生成映射、目录说明和清单校验。
2. `images/`、`archives/`、`markdown/` 保存格式能力、边界和错误样张；每个类型至少有一个真实耗时的加载样张，以文件读取、解码、条目枚举或语法解析产生工作量，不在程序或样张生成器里人为添加等待。记录文件规模、预期状态和适用场景；加载动画是否实际出现依机器性能判断，不把固定毫秒数当成样张属性。
3. 样张应可重复生成，内容不含私人文件、真实密码或预览时必须联网才能取得的资源。Markdown 可含普通链接以检验语法，但实际内容应能离线预览。除明确标注的损坏、加密和扩展名不符样张外，文件头、内容与扩展名应匹配。小样张优先；大样张要能验证明确的耗时或资源边界，避免无目的地增加仓库体积。不要让 `switching/` 重复存放大样张。
4. 生成器必须在没有 7-Zip/WinRAR 时明确复用已提交的对应文件，缺文件就失败，不允许默默跳过某类样张。`manifest.json` 必须列出所有可预览样张的相对路径、类别、场景、预期、字节数和 SHA-256；新增、删除或修改样张时同步更新。临时归档负载和中间记录放在忽略的 `out/test-fixture-work/`，不要留在 `test/`。
5. 变更后运行 `generate.py --verify`，确认清单与文件一致、没有游离样张、`switching/` 与工厂扩展名一致。需要验证实际预览行为时启动正式 `PreviewAll.exe`、勾选托盘类型，并在资源管理器预览窗格中查看、切换和关闭；不要以独立窗口或辅助 Smoke 程序作为最终验收。将当前实现尚不支持的行为写为预期失败，不把产品目标误写成已实现行为。
